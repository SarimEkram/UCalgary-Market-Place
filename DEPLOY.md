# Free Deployment Guide

This app deploys as **one free Render web service**: the Express backend builds
and serves the React frontend from the same origin, so there are no CORS or
cross-site-cookie problems. You also need a free **MySQL** host and a free
**Redis** host.

Local `docker compose up` is unaffected by any of this.

## 1. Create the free data services

**MySQL** — [Aiven](https://aiven.io) free tier (or Railway / PlanetScale). Note the
host, port, user, password, and database name. Hosted MySQL requires TLS.

**Redis** — [Upstash](https://upstash.com) free tier. Copy the `rediss://...`
connection URL. (If Redis is ever down, the app still runs; only rate limiting
is skipped.)

## 2. Load the database schema

Hosted MySQL rejects the docker `db/init.sql` (it uses `CREATE DATABASE`,
`SET GLOBAL`, and `LOAD_FILE`). Use the portable version instead:

```bash
mysql -h <DB_HOST> -P <DB_PORT> -u <DB_USER> -p <DB_NAME> < db/init.hosted.sql
```

> Seed **posts/users/events load, but seed product images do not** — `LOAD_FILE`
> can't run on a hosted DB. Images uploaded through the app at runtime work
> normally (they're stored as blobs in the `images` table).

## 3. Deploy to Render

Push this branch, then on [Render](https://render.com): **New → Blueprint**, pick
this repo. `render.yaml` defines the service. Fill in the env vars marked
"needs value" below in the Render dashboard.

| Variable | Value |
|---|---|
| `NODE_ENV` | `production` (preset) |
| `COOKIE_SECURE` | `true` (preset) |
| `JWT_SECRET` | auto-generated by Render |
| `CLIENT_ORIGIN` | the service's own URL, e.g. `https://seng513-marketplace.onrender.com` |
| `DB_HOST` `DB_PORT` `DB_USER` `DB_PASSWORD` `DB_NAME` | from your MySQL host |
| `DB_SSL` | `true` (preset) |
| `REDIS_URL` | the `rediss://...` URL from Upstash |
| `EMAIL_USER` `EMAIL_PASS` | Gmail address + [app password](https://support.google.com/accounts/answer/185833) |

After the first deploy, set `CLIENT_ORIGIN` to the real URL Render assigns, then
redeploy once.

## Known free-tier limitations

- **Cold starts.** Render's free service sleeps after ~15 min idle; the first
  request after that takes ~30–60s and live chat sockets reconnect.
- **Connection caps.** If your MySQL host limits connections, set
  `DB_CONNECTION_LIMIT` (e.g. `5`) to stay under it.
- **Email.** Gmail app passwords are rate-limited — fine for a demo.

## Reverting

All deploy changes live on the `deploy-free` branch. To undo:

```bash
git checkout main
```

To keep them, merge the branch. The code changes are backwards-compatible:
with no new env vars set, everything falls back to the original localhost /
docker-compose behavior.

## Alternative: split deploy (Vercel frontend + Render backend)

Not required, but if you prefer the frontend on Vercel's CDN: host the frontend
separately and set on the backend `COOKIE_SAMESITE=none`, `COOKIE_SECURE=true`,
and `CLIENT_ORIGIN=<your-vercel-url>`. You'll also need a `vercel.json` rewrite
proxying `/api` and `/socket.io` to the Render backend. The same-origin setup
above avoids all of that.
